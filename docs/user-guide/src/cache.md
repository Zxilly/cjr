# 缓存与 cjv

## 目录配置

cjr 默认使用用户目录下的 `.cjr`，可以通过 `CJR_HOME` 指定其他目录。

```sh
CJR_HOME=/path/to/cjr-cache cjr ./app
```

```powershell
$env:CJR_HOME = 'D:\Caches\cjr'
cjr .\app.exe
```

`CJR_HOME` 必须与 cjv 目录分离，二者不能相同或互相嵌套。使用当前用户可写的本地文件系统目录。

## 自动复用 cjv

已有 cjr 运行库直接使用。准备新运行库时，依次尝试：

1. cjv 中匹配官方摘要的下载归档。
2. cjv 中具有官方来源记录的受管 SDK 安装。
3. cjr 自己保存的下载归档。
4. 官方下载地址。

读取 cjv 安装时，cjr 与 cjv 使用兼容的锁协议。文件会复制到 cjr 的独立运行库目录；cjr 不修改、修复或清理 cjv 的内容。

cjr 首先读取绝对路径 `CJV_HOME`。未设置时，使用 cjv 用户配置中的 `home`，再尝试系统配置，最后使用用户目录下的 `.cjv`。`CJV_CONFIG_FILE` 和 `CJV_FALLBACK_SETTINGS` 可分别指定这两份配置文件。

旧缓存布局、自定义 SDK 或来源不明的安装不会直接使用。没有可用 cjv 内容时，cjr 自动尝试下一来源。

## 清理时跳过的内容

启动目标程序前，cjr 会登记运行库使用记录。程序或其后台子进程可能仍在使用运行库时，`cache clean --all` 会跳过它。

macOS 无法可靠确认所有后代进程退出，因此使用记录可能保留到同一主机下次启动。cjr 被强杀或记录无法读取时，也可能暂时不能回收对应运行库。

清理不会删除协调锁或跟随链接清理外部目录。不建议手动删除正在使用的运行库目录。
