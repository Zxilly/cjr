# 缓存与 cjv

## 目录配置

cjr 默认使用用户目录下的 `.cjr`，可以通过 `CJR_HOME` 指定其他目录。

```sh
CJR_HOME=/path/to/cjr-cache cjr ./app
```

```powershell
$env:CJR_HOME = 'D:\Caches\cjr'
cjr .\app.exe
```

`CJR_HOME` 与 cjv 目录须各自独立，位于互相分离的路径下。使用当前用户可写的本地文件系统目录。

## 自动复用 cjv

已有 cjr 运行库直接使用。准备新运行库时，依次尝试：

1. cjv 中匹配官方摘要的下载归档。
2. cjv 中具有官方来源记录的受管 SDK 安装。
3. cjr 自己保存的下载归档。
4. 官方下载地址。

读取 cjv 安装时，cjr 与 cjv 使用兼容的锁协议。文件会复制到 cjr 的独立运行库目录；cjv 的内容保持原样。

cjr 首先读取绝对路径 `CJV_HOME`。未设置时，使用 cjv 用户配置中的 `home`，再尝试系统配置，最后使用用户目录下的 `.cjv`。`CJV_CONFIG_FILE` 和 `CJV_FALLBACK_SETTINGS` 可分别指定这两份配置文件。

cjr 使用布局兼容且来源记录完整的官方 SDK 缓存与受管安装。其余内容会被跳过，并自动尝试下一来源。

## 清理时跳过的内容

启动目标程序前，cjr 会登记运行库使用记录。程序或其后台子进程可能仍在使用运行库时，`cache clean --all` 会跳过它。

macOS 上，后代进程的退出状态可能需要等到同一主机下次启动才能确认，使用记录会保留到确认完成。cjr 被强杀或记录读取失败时，对应运行库也会保留以供后续确认。

清理会保留协调锁，处理范围限定在 cjr 目录内的文件和链接本身。请使用 `cjr cache clean`，由它根据使用记录判断可回收的运行库。
